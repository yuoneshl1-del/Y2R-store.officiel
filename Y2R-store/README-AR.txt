Y2R — نسخة العرض الجامعي (Prototype)
===================================

ما هو المشروع؟
متجر إلكتروني تجريبي للأحذية، مع لوحة إدارة الطلبات، إدارة المخزون حسب المقاس، تتبع وإلغاء الطلب، مؤشرات تحليلية، وتصدير تقارير.

المزايا المتوفرة في هذه النسخة:
- متجر للمنتجات مع بحث/تصنيف/مفضلة وفلتر السعر (حسب الواجهة الحالية).
- سلة وطلب تجريبي مع التحقق من بيانات العميل ورقم هاتف جزائري.
- المخزون حسب المقاسات 36 إلى 45، وتكلفة شراء اختيارية للمنتج.
- منع الطلب عندما يكون المخزون غير كافٍ، والتحقق من إجمالي الكمية حتى لو تكرر المنتج والمقاس في السلة.
- خصم المخزون عند إنشاء الطلب، وإرجاع الكمية عند إلغاء الطلب من العميل أو المدير ضمن الحالات المسموحة.
- تتبع الطلب برقم الطلب ورقم الهاتف.
- لوحة إدارة محمية بمفتاح، وبحث/فلترة الطلبات وتغيير الحالات.
- مؤشرات مبيعات ومقاسات ومنتجات، وتصدير CSV وExcel-compatible.
- نقطة صحة الخادم: /api/health
- اختبار دخان آلي يعمل في مجلد مؤقت ولا يغيّر بيانات العرض: npm run test:smoke

التشغيل على Windows:
1) ثبّت Node.js 18 أو أحدث من الموقع الرسمي.
2) فك ضغط ZIP كاملًا.
3) شغّل INSTALL-AND-RUN.bat. أول تشغيل يطلب مفتاح مدير، ثم يثبت الاعتماديات ويفتح المتجر.
4) المتجر: http://localhost:3000
5) لوحة الإدارة: http://localhost:3000/admin.html
6) افتح نافذة Terminal التي تشغّل الخادم؛ المفتاح يظهر في سجلات التشغيل إذا لم يكن مضبوطًا.

التشغيل يدويًا:
- افتح Terminal داخل مجلد Y2R-store.
- npm ci
- أنشئ ملف .env باستخدام .env.example، وحدد ADMIN_KEY قويًا خاصًا بك.
- npm start (أو npm run dev أثناء التطوير)
- افتح http://localhost:3000

اختبار سريع:
- npm run test:smoke
- يفحص صحة الخادم، المنتجات، حماية لوحة الإدارة، المخزون، إنشاء الطلب، تتبعه، إلغاءه، وإرجاع المخزون.

البيانات:
- المنتجات: data/products.json
- الطلبات التجريبية: data/demo-orders.json
- المخزون: data/inventory.json
- تقارير/قوالب: public/downloads (إن وجدت)
- خذ نسخة احتياطية من مجلد data قبل أي تعديل.

ملاحظات مهمة للعرض الجامعي:
- الأرقام والطلبات المضمنة بيانات تجريبية وليست مبيعات حقيقية.
- لا تستخدم النسخة الحالية لجمع بيانات زبائن حقيقية أو البيع الحقيقي.
- تخزين JSON ليس قاعدة بيانات إنتاجية، ولا يدعم ضمانات المعاملات أو التوسع متعدد المستخدمين.
- لا توجد بوابة دفع إلكتروني أو ربط مؤكد مع شركة توصيل.
- قبل إطلاق حقيقي: قاعدة بيانات مناسبة، HTTPS، سياسة خصوصية وشروط، حماية جلسات/مدير، نسخ احتياطي، تدقيق أمني، سجل تعديلات، إعداد التوصيل والدفع والبيانات التجارية.
- ميزة تحليل الطلب الحالية مؤشرات وصفية من البيانات، وليست نموذج ذكاء اصطناعي مدرب.
- ملف Excel export يتيح إدخال المصاريف يدويًا؛ الربح يظل تقديريًا عندما تكون التكلفة أو المصاريف ناقصة.

لرئيس القسم:
يُقدَّم المشروع كنموذج أولي قابل للدراسة والتطوير. لا يُدّعى أنه اختراع مسجل أو أنه فريد بالسوق دون بحث سابق ومقارنة موثقة.


تحديث إدارة المخزون (نسخة الألوان والمقاسات):
- المخزون مستقل لكل لون ولكل مقاس من 36 إلى 45.
- افتح /inventory.html من رابط إدارة المخزون وسجّل الكميات لكل لون ثم اضغط حفظ اللون.
- في صفحة المنتج، اختيار اللون يغيّر الكميات المتاحة للمقاسات؛ المقاسات التي مخزونها صفر تكون غير قابلة للاختيار. المتجر يحدّث المخزون تلقائيًا كل 20 ثانية، وكذلك بعد تسجيل الطلب.
- الطلب يخصم من مخزون اللون والمقاس المختار، وإلغاء الطلب المسموح يعيد نفس الكمية لنفس اللون والمقاس.
- إذا كانت بيانات المخزون قديمة بصيغة المقاسات فقط، يرحّل الخادم الكميات القديمة إلى اللون الأول للمنتج ويبدأ باقي الألوان من صفر.
